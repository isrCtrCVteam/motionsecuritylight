The written project page

Motion Security Light

PORCHLIGHT · An interactive model of an automatic control system.

The problem

A porch light is useful when someone arrives after dark, but a light left on continuously uses electricity when nobody needs it. This project explores how an automatic system can respond to movement, filter small inputs and switch off after a delay.

Our solution

Porchlight is a self-contained webpage built with HTML, CSS and JavaScript. A visitor can generate simulated motion, change a detection threshold, compare day and night, and watch the light respond. It runs without an account, installation, external libraries or a Micro:bit.

Demonstration scope: all sensor values are simulated. The page does not use a camera, detect real movement, measure infrared radiation or control a physical light.

Input → Process → Output

Input

Wave Hand produces an abstract signal of 85%. Weak Motion produces 25%. The signal returns to zero after a short pulse. A day/night switch represents the ambient condition.

Process

The program compares the signal with a stored threshold. A value at or above the threshold gives a decision bit of 1; a lower value gives 0. A second rule checks whether lighting is allowed in the current day/night setting.

Output

If both checks pass, the porch lamp turns on. A countdown keeps it on for the selected time. A new accepted input restarts the countdown; expiry switches the lamp off.

Binary, used accurately

The 0/1 display is a Boolean comparison result. The eight digits show recent results, not an 8-bit analogue-to-digital conversion. Motion can be detected during the day while the light stays off.

The log holds the newest 30 events for the current session. Refreshing the page clears its data. Reset Demo restores the initial settings and clears the log; Clear removes only the log.

How to check it

At night with threshold 50%, weak motion at 25% should be ignored and a wave at 85% should switch on the light. Lower the threshold to 20%: the same weak input should now be accepted. At threshold 90%, even a wave should be ignored. During the day with night-only mode enabled, an 85% signal should show motion bit 1 but leave the lamp off. Wait for a countdown to finish, then repeat a wave before expiry to test the timer restart.

Limits and next steps

The simulation illustrates a control rule; it is not a calibrated PIR sensor. Real passive infrared sensors respond to changes in infrared radiation, and their output depends on the hardware. A future extension could use a Micro:bit's light-level changes as a proxy input, or connect a real PIR sensor. Neither hardware path is implemented here. No energy savings have been measured.

Understand the code.

The important ideas are comparison, conditions, state and timing.

The decision in three lines

const motion = signal >= threshold;
const allowed = !nightOnly || isNight;
if (motion && allowed) turnLightOn();

>= means “greater than or equal to”. ! means NOT, || means OR and && means AND. Motion must pass the threshold and lighting must be allowed.

Example: at night, a signal of 85 and a threshold of 50 make both checks true. In daytime with night-only mode enabled, the motion check remains true but the allowed check becomes false.

Be ready to explain

Does the website detect a real hand?

No. The button generates a simulated input. A real sensor would need a hardware connection and additional code.

Why is the threshold stored?

It is the reference value used for comparison. Changing it changes which inputs the program accepts.

Why does the lamp stay on after the motion bit returns to 0?

The input is a short pulse. The light has a separate hold timer, so it remains useful while the visitor approaches the door.

Why does 1 not always mean the light is on?

The bit describes the motion comparison. The daylight rule can block the final output even when motion is detected.

What happens if another visitor arrives?

A new accepted input sets a new deadline. The light remains on for the selected duration after the most recent accepted input.

Is this a feedback loop?

There is no measurement of the actual lamp's light output here. It is an input-driven simulation with a timed output, not a closed-loop brightness controller.

What do HTML, CSS and JavaScript do?

HTML defines the content, CSS controls appearance and animation, and JavaScript implements the decisions, timers and event log.

How would you improve it next?

Connect a real sensor and validate its readings. Then investigate noise, calibration and safe control of a physical low-voltage light.
